# React — Rendering Lists with `.map()` (Movie Cards App)

This module covers a common, foundational React pattern: taking an **array of data** and rendering it as a **grid of UI cards** — using `.map()`, the `key` prop, and a CSS Grid layout.

---

## 1. The Data Source — `movies.js`

```js
let movieData = [
  {
    id: 1,
    name: "Whiplash",
    year: 2014,
    runningTime: "106 Minutes",
    directedBy: "Damien Chazelle",
    producedBy: "Jason Blum",
    starring: "Miles Teller, J.K. Simmons",
    url: "https://..."
  },
  // ... 11 more movie objects
];

export default movieData;
```

- A plain **array of objects**, each with the same consistent shape (`id`, `name`, `year`, `runningTime`, `directedBy`, `producedBy`, `starring`, `url`).
- Kept in its own file (`movies.js`) and exported as the **default export**, separating raw data from the component that displays it — a clean separation of concerns even for static/mock data.
- Each object has a unique `id` field — this becomes important in Section 3, when rendering the list.

---

## 2. `Cards.jsx` — Turning Data into UI

```jsx
import React, { useState } from "react";
import movieData from "./movies.js";

const Cards = () => {
  const [movies, setMovies] = useState(movieData);
  return (
    <div className="grid">
      {movies.map((movie, index) => (
        <div className="movie-card" key={movie.id}>
          {/* ... */}
        </div>
      ))}
    </div>
  );
};

export default Cards;
```

### 2.1 Why `useState(movieData)` at All?

```js
const [movies, setMovies] = useState(movieData);
```

- Right now, `movies` is **never actually modified** anywhere in this component — `setMovies` is destructured but never called. So functionally, this component would currently render identically if it just did `const movies = movieData;` with no `useState` at all.
- **Why wrap it in state anyway?** This is a common, intentional setup pattern: by putting the data in `useState` from the start, the component is **ready** for future interactivity — sorting, filtering, adding/removing movies, favoriting, etc. — without needing to refactor the component's data source later. You'd just start calling `setMovies(...)` somewhere (e.g., a sort button, a search filter) and the grid would automatically re-render with the new list.
- If this data were **guaranteed to never change** for the lifetime of the app, skipping `useState` and just using the imported `movieData` directly would be simpler and slightly more efficient (one less piece of state for React to track). The choice to use `useState` here signals "this list is expected to become dynamic."

### 2.2 `.map()` — Turning an Array into JSX Elements

```jsx
{movies.map((movie, index) => (
  <div className="movie-card" key={movie.id}>
    ...
  </div>
))}
```

- `.map()` is a native JavaScript array method: it runs a function on **every item** in the array and returns a **new array** of whatever that function returns.
- Here, the function returns a **JSX element** for every `movie` object — so `.map()` transforms the array of 12 movie *objects* into an array of 12 movie *card elements*.
- **React can render an array of JSX elements directly** — placing `{movies.map(...)}` inside the JSX tree tells React "render each of these elements, one after another," which is exactly how you turn a list of data into a list of UI without manually writing 12 separate `<div>` blocks.
- `(movie, index)` — `.map()`'s callback always receives the current item first, and its numeric index second. Here, `index` is destructured but **not used** anywhere in the JSX (the code uses `movie.id` instead — see below), so it could be safely omitted from the parameters.

---

## 3. The `key` Prop — Why `key={movie.id}` and Not `key={index}`

```jsx
<div className="movie-card" key={movie.id}>
```

- Whenever you render a list of elements from `.map()`, React requires a special **`key` prop** on each top-level element in the list — it's how React's diffing algorithm identifies *which* element is which across re-renders, rather than just comparing positions.
- **`key` must be:**
  - **Unique** among siblings in that list
  - **Stable** — the same item should keep the same key across re-renders, even if the list gets reordered, filtered, or has items added/removed

### Why `movie.id` is the Right Choice Here

- Each movie object already has a genuinely unique `id` field (`1` through `12`), so `key={movie.id}` gives React a **stable identity per movie**, independent of where that movie sits in the array.
- This is a better choice than `key={index}` (used in some of your earlier notes, on lists that only ever *append*). If this list were ever sorted, filtered, or had an item removed from the middle, index-based keys would shift and cause React to misattribute state/DOM nodes to the wrong items — `id`-based keys avoid that entirely, since a movie's `id` never changes no matter where it ends up in the array.
- **Rule of thumb:** always prefer a genuinely unique, stable field (like a database `id`) as your `key` over the array `index`, whenever one is available.

## 4. Displaying Each Movie's Data

```jsx
<div className="movie-card" key={movie.id}>
  <img src={movie.url} className="poster" alt={movie.name} />
  <div className="details">
    <div className="title">
      <h1>{movie.name.toUpperCase()}</h1>
      <span>{movie.year}</span>
    </div>
    <div className="desc">
      <div className="sub-desc">
        <h2>running time</h2>
        <span>{movie.runningTime}</span>
      </div>
      <div className="sub-desc">
        <h2>directed by</h2>
        <span>{movie.directedBy}</span>
      </div>
      <div className="sub-desc">
        <h2>produced by</h2>
        <span>{movie.producedBy}</span>
      </div>
    </div>
    <div className="sub-desc">
      <h2>starring</h2>
      <span>{movie.starring}</span>
    </div>
  </div>
</div>
```

- **`movie.name.toUpperCase()`** — a plain JS string method called inline inside the JSX expression `{}`. Note that `.title h1` in the CSS *also* has `text-transform: uppercase` — meaning the uppercase transform is technically applied **twice** here (once by JS, once by CSS). Either one alone would be sufficient; this is harmless redundancy rather than a bug, but worth knowing if you ever change the CSS and wonder why the text is still uppercase.
- **`alt={movie.name}`** — good practice: gives each poster image meaningful alt text for accessibility/screen readers, using the movie's actual name rather than a generic placeholder.
- Every other field (`year`, `runningTime`, `directedBy`, `producedBy`, `starring`) is rendered as plain text inside JSX expressions — no transformation applied, just direct interpolation of the object's values.
- Notice that `starring` (which contains a comma-separated string like `"Miles Teller, J.K. Simmons"`) is stored and rendered as a **single string**, not an array — simpler for this dataset, though if you later wanted to style or link each actor individually, you'd likely restructure it as an array (e.g. `starring: ["Miles Teller", "J.K. Simmons"]`) and `.map()` over it the same way the outer movie list is mapped.

## 5. `App.jsx` & `main.jsx` — Entry Point

```jsx
// App.jsx
import React from 'react'
import Cards from './Cards'

const App = () => {
  return (
    <main>
      <Cards />
    </main>
  )
}

export default App
```

```jsx
// main.jsx
import { createRoot } from 'react-dom/client'
import './index.css'
import App from './App.jsx'

createRoot(document.getElementById('root')).render(<App />)
```

- `App` is intentionally minimal here — its only job is to wrap `Cards` inside a semantic `<main>` element. There's no state or logic in `App` itself; all the interesting behavior lives in `Cards`.
- `main.jsx` follows the same standard entry-point pattern from your earlier notes: import the global stylesheet, mount `App` into the real `#root` DOM node via `createRoot(...).render(...)`.

## 6. `index.css` — Styling the Grid & Cards

### 6.1 Global Setup

```css
@font-face {
  font-family: 'tall';
  src: url('./font.ttf');
}

::-webkit-scrollbar {
  display: none;
}
```

- A custom local font (`tall`) is registered and applied globally via the `*` selector — every element in the app uses this font by default (unlike earlier examples where the custom font was scoped to just one heading).
- `::-webkit-scrollbar { display: none; }` **hides the scrollbar** entirely in WebKit-based browsers (Chrome, Edge, Safari) — a purely cosmetic choice; the page is still scrollable, the scrollbar track/thumb is just invisible. Note this rule has **no effect** in Firefox, which uses a different (non-`::-webkit-`) mechanism for scrollbar styling.

### 6.2 The Grid Layout

```css
.grid {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  gap: 20px;
  padding: 20px;
}
```

- `display: grid` turns the container into a CSS Grid.
- `grid-template-columns: repeat(4, 1fr)` creates **exactly 4 equal-width columns** — `repeat(4, 1fr)` is shorthand for `1fr 1fr 1fr 1fr` (four fractional units, each getting an equal share of the available width).
- `gap: 20px` puts consistent spacing between every card, both horizontally and vertically, without needing manual margins on each card.
- **Note:** this grid is currently **fixed at 4 columns** regardless of screen size — there are no `@media` breakpoints here (unlike the responsive login/register layout from earlier notes) to reduce the column count on smaller screens. On a narrow viewport, all 4 columns would be squeezed very tight. If you wanted this to adapt, you could add breakpoints (e.g. 2 columns on mobile) the same way you did in that earlier project, or use `grid-template-columns: repeat(auto-fit, minmax(220px, 1fr))` to let the grid decide the column count automatically based on available space.

### 6.3 Card Styling — `aspect-ratio` for Consistent Card Shapes

```css
.movie-card {
  background: #dbdcd5;
  color: #2c2c2b;
  padding: 18px;
  box-shadow: inset 0 0 0 5px white;
  display: flex;
  flex-direction: column;
  gap: 15px;
  aspect-ratio: 2 / 3;
}
```

- **`aspect-ratio: 2 / 3`** forces every card to maintain a **2:3 width-to-height ratio**, no matter how much content is inside it — this is what gives the grid its uniform, poster-like card shapes (taller than they are wide), regardless of how much text a given movie's details contain.
- **`box-shadow: inset 0 0 0 5px white`** — an interesting trick: an `inset` shadow with **no blur** (`0 0`) and a `5px` spread acts as a solid **inner border**, effectively giving the card a 5px white frame *inside* its edges, without affecting the box's outer dimensions the way an actual `border` property would (a real border adds to the element's size unless `box-sizing: border-box` compensates for it — this shadow-based trick sidesteps that entirely).
- The card itself is a flex column (`display: flex; flex-direction: column`), stacking the poster image and details vertically, with a consistent `15px` gap between them.

### 6.4 The Poster Image

```css
.movie-card img {
  width: 100%;
  aspect-ratio: 4 / 3;
  object-fit: cover;
}
```

- The image is forced to a **4:3 aspect ratio** of its own (wider than tall), independent of the card's own 2:3 ratio — this keeps posters looking consistent across cards even if the original source images have very different natural dimensions (as they do here — some are wallpapers, some are official posters, some are screenshots).
- `object-fit: cover` ensures the image **fills** that 4:3 box completely, cropping any excess rather than squashing or letterboxing it — the same technique used for the profile images in your earlier `UserCard` component.

### 6.5 Details Section Layout

```css
.details {
  display: flex;
  flex-direction: column;
  gap: 12px;
  flex: 1;
}
```

- `flex: 1` tells `.details` to **grow and fill** whatever vertical space remains inside `.movie-card` after the poster image takes its share — this is what pushes the "starring" section down toward the bottom of the card consistently, rather than everything clustering tightly at the top regardless of card height.

```css
.title {
  display: flex;
  justify-content: space-between;
  align-items: baseline;
}
```

- The movie name and year sit on the **same row**, pushed to opposite ends (`justify-content: space-between`) — e.g. `WHIPLASH` on the left, `2014` on the right.
- `align-items: baseline` aligns the two text elements along their **text baseline** rather than their box edges — a subtle but important detail, since the name (`42px`, very large) and the year (`18px`, much smaller) would otherwise look visually misaligned if centered or top-aligned normally; baseline alignment makes both sit as if resting on the same invisible line, matching how text naturally reads.

```css
.sub-desc {
  display: flex;
  justify-content: space-between;
  align-items: baseline;
  margin-bottom: 7px;
}
```

- The same left/right-split, baseline-aligned pattern is reused for every label/value pair (`running time` / `106 Minutes`, `directed by` / `Damien Chazelle`, etc.) — consistent visual rhythm achieved by reusing one class across multiple repeated rows, rather than writing bespoke CSS for each.

## Quick Summary

```
Array of data (movies.js) → .map() → array of JSX elements → rendered as a list

.map((item, index) => <Component key={UNIQUE_STABLE_VALUE} .../>)
  - key should be a genuinely unique, stable identifier (e.g. item.id)
  - prefer this over `key={index}` whenever a stable id is available,
    especially if the list could ever be reordered/filtered/have items removed

useState(staticData) even when unused yet:
  - signals "this data is expected to become interactive later"
  - functionally identical to a plain const until setMovies is actually called somewhere

CSS Grid card layout:
  grid-template-columns: repeat(4, 1fr)  → N equal columns
  aspect-ratio: W / H                     → forces consistent card/image shapes
  object-fit: cover                       → crops images to fill their box without distortion
  box-shadow: inset 0 0 0 Npx color       → a border that doesn't affect box sizing
```
